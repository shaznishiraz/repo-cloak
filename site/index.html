Share private code with AI agents, without sharing your secrets.

repo-cloak copies the files you choose from a private Git repository into a separate workspace, anonymizes company names, paths, and secrets, and restores every change the agent makes with the original names intact.

How it works

  1. 1

    Cloak

    Run repo-cloak in your repository. Pick profiles and files, preview every replacement, and get an anonymized workspace.

  2. 2

    Work

    Point your AI agent at the workspace. It sees consistent placeholder names, never your company, clients, or keys.

  3. 3

    Restore

    Run repo-cloak push. Changes go back with the original names, checked for conflicts first, and left uncommitted for your review. 

  your repo            repo-cloak push            cloak workspace
 ┌───────────┐   anonymize names + secrets   ┌──────────────────┐
 │ Acme Corp │ ────────────────────────────► │ Northwind Traders│ ◄── AI agent
 │ ACME_KEY  │ ◄──────────────────────────── │ REDACTED_KEY_1   │
 └───────────┘   restore, conflict-checked   └──────────────────┘
                     repo-cloak push

Features

Case-aware anonymizer

One rule covers AcmeCorp, acmeCorp, acme_corp, ACME_CORP, and acme-corp, keeping each style. Identifier boundaries leave unrelated words alone.

Regex and secret detection

Add regex rules with capture groups, and use built-in detectors that replace keys and tokens with placeholders, which are restored on the way back.

Exact, safe restore

Every affected file is checked before writing. Source changes stop the restore with a conflict instead of overwriting your work.

Encrypted by default

Original names, paths, and replacement pairs are encrypted with a machine-local key. The workspace only exposes anonymized paths and hashes.

Git worktree aware

Workspaces link to a branch. Restore into an existing worktree, or create a new one from the exact commit you started from with --new-worktree.

Reusable profiles

Keep rules in global or per-repo profiles and combine them. Conflicting rules are caught before anything is written.

Local dashboard

repo-cloak ui opens one dashboard for all your repos and workspaces, bound to 127.0.0.1 and protected by a session token.

Built for scripts and agents

--dry-run, --yes, and --json for scripted runs, plus JSON Schemas for profiles and manifests that tools and LLMs can follow.

Works from either side

pull brings changes here, push sends them to the other side, whether you are in the source repo or the workspace.

Usage

Guided

Run it with no arguments in your repository and follow the prompts.

# in your source repository
repo-cloak

Explicit

# create a profile (opens a validated JSON editor)
repo-cloak profile create company

# preview, then create the anonymized workspace
repo-cloak push --profile repo:company --files src README.md \
  --to ../cloak-work --dry-run
repo-cloak push --profile repo:company --files src README.md \
  --to ../cloak-work --yes

# after the agent's changes, in the workspace
cd ../cloak-work
repo-cloak status
repo-cloak push

FAQ

How do I share private code with an AI agent without exposing company names?

Run repo-cloak in your repository, choose the files, and give the agent the anonymized workspace it creates. Names, paths, and detected secrets are replaced; repo-cloak push restores the agent's changes with the original names.

Does it handle camelCase, snake_case, and uppercase names?

Yes. One literal rule covers variants such as AcmeCorp, acmeCorp, acme_corp, ACME_CORP, and acme-corp, keeps each case style, and respects identifier boundaries so unrelated words are left alone.

Can it overwrite my work when restoring?

Restore checks every affected file first. If a source file changed since it was anonymized, restore stops with a conflict and exit code 2 instead of overwriting it. Restored changes stay uncommitted for review.

Where are the original names stored?

Original names, paths, and replacement pairs are encrypted with a machine-local key in ~/.repo-cloak. Keep that key backed up: without it, a workspace cannot be restored.

Does it work with Git worktrees?

Yes. Workspaces are linked to a branch, and repo-cloak push --new-worktree restores changes into a new Git worktree based on the commit the files were taken from.

What does it need?

Node.js 22.13 or later, and Git, on macOS, Windows, or Linux.
